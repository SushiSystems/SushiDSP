# Documentation style guide

Where a document goes, how the changelog is shaped and how a work folder lives follow the
`documentation` skill. Prose follows the `humanizer` skill, in the language it is written in.
Source comments follow `source-comments`. None of the three is restated here; this page holds
what is particular to SushiDSP. [`CONTRIBUTING.md`](CONTRIBUTING.md) says what a change must
document.

## The tree as it stands

```
README.md                        the front door
CLAUDE.md  AGENTS.md             agent instructions
docs/
  README.md                      the manual index
  CONTRIBUTING.md
  DOCUMENTATION_STYLE_GUIDE.md
  getting_started/               the first-run sequence
  architecture/                  the layers as built, and the module index
  guides/                        the command line
  reference/
    API_REFERENCE.md             the page Doxygen opens the generated reference with
    CHANGELOG.md  GLOSSARY.md  KNOWN_ISSUES.md
    spice/                       the LTspice corpus: schematics, models, CSVs, one README per block
  design/                        live intent, one document per topic, plus the map and the backlog
  agent/                         one folder per piece of agent work
  archive/                       frozen
modules/<tier>/<module>/README.md
applications/host_gui/  cli/  assets/<name>/  tools/  tools/<name>/  modules/foundation/golden_compare/  each with a README.md
```

`sd docs` writes the generated API reference to `build/docs/api-site/html/`. It is build
output and is never edited or committed.

## What a module README holds

A fact about one module is written in that module's `README.md` and nowhere else.
[`architecture/MODULES.md`](architecture/MODULES.md) links to it and repeats none of it. A
module README in this repository carries, in this order where they apply:

1. What the node is and the id it registers under.
2. Which class owns which block of the circuit or the signal path.
3. Where each constant comes from: read off a schematic, derived from one with the arithmetic
   shown, or measured.
4. The stand-in table: every figure nobody has published, what stands in for it and what would
   settle it.
5. Where the module departs from the design document.

## The manual index

`docs/README.md` is a set of tables, one row per document: a link and one clause saying what
the document holds. It states no fact of its own about the thing documented.

## The SPICE corpus

`docs/reference/spice/` holds data beside its prose because each block's README describes the
netlist in the same folder. A block README says what the block is, how its schematic is
written, its components and values, the probe, the stepped control and the judgement calls
behind the netlist. The CSVs are generated by `tools/spice/export.py` and committed.

## Figures

A measured figure is written with its unit, the conditions it was measured under and the test
or tool that reproduces it: "−23.4 dB through `measure::alias_floor()` at preamp 1.0 and a
−12 dBFS input". A figure without the three is not written down.

## Words

English, British spelling in prose ("licence" the noun, "catalogue"). Identifiers keep the
spelling the code uses, such as `serialize_rig_to_json` and `K_LICENSE_LINES`. Manufacturer and
product names say which circuit a model was written against; [`NOTICE.md`](../NOTICE.md) holds
the trademark position.

## Links and paths

A path cited in prose is a real path in the tree, spelled as the tree spells it. A link is
relative to the file that carries it. An example path sits in a code span and is not a link.
