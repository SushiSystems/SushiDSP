# Yamaha SPX90 / SPX90II — Research Dossier for a High-Accuracy Software Model

Compiled 2026-08-26. Every factual claim carries a source URL and a confidence rating.

Confidence key: **High** = Yamaha's own manual/service manual or a primary datasheet; **Med** = credible secondary source, consistent across independent sources; **Low** = forum lore / single unverified source.

**CORRECTION to the brief's premise.** The SPX90**II** is *not* 44.1 kHz. Yamaha's own SPX90II specification lists 31.25 kHz / linear 16 bit / 20 Hz–12 kHz, identical to the SPX90. The II is the same engine with **more delay RAM** (longer delays, 2 s Freeze vs 500 ms, wider parameter ranges, ±2 octave pitch shift) plus cosmetic changes — not a higher sample rate. Source: [SPX90II specs](https://www.vintagedigital.com.au/yamaha-spx90ii-multi-effects-processor/). Confidence: **High**. Any 44.1 kHz claim for the SPX90II should be treated as wrong.

### 1.2 Silicon

| Part | Role | Notes | Source | Confidence |
|---|---|---|---|---|
| **YM3804** ("DSP") | The reverb/delay signal processor | Executes **64 instructions per sample**. At 31.25 kHz that is a ~2.0 MHz instruction rate — the *entire* algorithm budget is 64 ops/sample. SPX90 has **one**. | [SPX90 service manual text](https://archive.org/stream/yamaha_yamaha_spx90/yamaha_spx90_djvu.txt); [acreil, Gearspace](https://gearspace.com/board/electronic-music-instruments-and-electronic-music-production/1044381-yamaha-fx-units-ym3413.html) | High (part no.) / Med (64-instr figure) |
| **YM3807** ("MOD", Modulation Data Generator) | ~16 independent LFOs with arbitrary waveforms; modulates **read addresses and gain coefficients** inside the YM3804 | This is the mechanism behind chorus/flange/symphonic/pitch-shift and any reverb-tail modulation | same as above | High (part no.) / Med (16-LFO figure) |
| **M5M4416** | 64 kbit DRAM (16 K x 4) — delay memory | 10 pcs in the service-manual parts list | [service manual text](https://archive.org/stream/yamaha_yamaha_spx90/yamaha_spx90_djvu.txt) | Med |
| **TC5565L-12** | 64 kbit SRAM (8 K x 8) — program/user memory | 21 pcs in parts list | same | Med |
| **PCM54HP** | Burr-Brown 16-bit monolithic DAC | in parts list; confirms a true 16-bit output converter | same | Med |

**Delay memory:** ~**16 kWords at 31.25 kHz ≈ 524 ms**, which exactly explains the SPX90's 500 ms max delay and 500 ms Freeze. The SPX90II raises this (2 s Freeze implies roughly 64 kWords). The later YM3413 repackaging supports up to 64 kWords. Source: [acreil, Gearspace](https://gearspace.com/board/electronic-music-instruments-and-electronic-music-production/1044381-yamaha-fx-units-ym3413.html). Confidence: **Med** — a forum claim, but it is internally consistent with the published max delay times and with the DRAM part count, which is strong corroboration.

**Family lineage (same silicon = same sonic family):** SPX90, SPX90II, SPX50D, REX50, GEP50 (1 x YM3804 + 1 x YM3807); **REV7** (2 x YM3804 + 1 x YM3807); **REV5** (3 x YM3804 + 1 x YM3807 + YM3608 DEQ). Later repackaged as **YM3413 (LDSP)** for reverb/delay and **YM3415 (LEF)** for modulation — found in FX900, R100, TG33, SY22/35/55/77, V50, TQ5. Sources: [acreil, Gearspace](https://gearspace.com/board/electronic-music-instruments-and-electronic-music-production/1044381-yamaha-fx-units-ym3413.html), [dtech.lv Yamaha chip list](http://www.dtech.lv/techarticles_yamaha_chips.html). Confidence: **Med**.

Practical consequence: a **Yamaha FX900 or R100** is a cheaper, more available donor running essentially the SPX90 reverb code on the YM3413. Useful as a second reference unit, and the reason a REV7 sounds like a "bigger SPX90" — it is literally 2x the same DSP.

### 1.3 Anti-alias / reconstruction filtering

Not documented numerically in any source found. What *is* documented is the outcome: effect path 20 Hz–12 kHz, bypass 20 Hz–20 kHz. A 12 kHz corner against a 15.625 kHz Nyquist implies a steep multi-pole analogue brickwall (elliptic or Chebyshev, likely switched-capacitor or active) on both the ADC input and the DAC output. **The exact topology, order and cutoff must be measured from a real unit.** Confidence: **Low** on any specific filter design; **High** on the ~12 kHz effective corner.

**The single most important architectural finding.** On the SPX90, GATE REVERB (16) and REVERSE GATE (17) are typed **E/R 2** in Yamaha's own table — they run the *early-reflection* engine, i.e. a **tapped-delay-line convolution with a finite, shaped tap set**, not a recirculating reverb followed by an envelope gate. That is a fundamentally different DSP structure (and a much easier one to match exactly, since a finite tap set is fully characterised by its impulse response). Modelling those two presets as "reverb + gate" will never null against the hardware. Confidence: **High** (preset type column in the manual).

| Parameter | Range |
|---|---|

| DELAY (pre-delay) | 0.1 – 50.0 ms |

Note there is **no explicit density or diffusion control** on the SPX90 (unlike the REV1/REV7, which expose Diffusion and Liveness separately). Pre-delay on the reverbs maxes at only **50 ms**, which is a hard constraint worth honouring in a model.

**DELAY (7)** — L/R delay 0.1–500.0 ms each; L/R feedback -99 % … +99 % (note the *negative*, polarity-inverted feedback range); FEEDBACK HIGH damping 0.1–1.0.

**MOD (9–15)** — MOD FREQ 0.1–20.0 Hz; MOD DEPTH 0–100 %; MOD DELAY TIME 0.1–100 ms (flange); F.B. GAIN 0–99 % (flange).

**PITCH CHANGE (21–24)** — PITCH -12 … +12; FINE -100 … +100; DELAY 0.1–400 ms (A, B, D), 0.1–200 ms (C); F.B. GAIN 0–99 % (A, D); BASE KEY OFF, C1–C6 (A, D).

**FREEZE (25–26)** — REC MODE manual/auto; TRIGGER DELAY -500 … +500 ms.

**GATE / ADR-NOISE GATE (18)** — TRIGGER LEVEL 1–100 %; TRIGGER DELAY -100 … +100 ms; ATTACK 5–32 000 ms; HOLD 1–30 000 ms; RELEASE 5–32 000 ms.

**PAN (27–28)** — PAN SPEED 0.1–20.0 Hz; DEPTH 0–100 %.

**DELAY VIBRATO (29)** — VIB FREQ 0.1–20.0 Hz; VIB DEPTH 0–100 %.

**PARAMETRIC EQ (30)** — HPF THRU/32 Hz–1.0 kHz; MID FRQ 315 Hz–4.0 kHz; MID GAIN -15…+15 dB; HI FRQ 800 Hz–8.0 kHz; HI GAIN -15…+15 dB; LPF 1 kHz–11 kHz/THRU; DELAY 0.1–400.0 ms.

**SPX90II differences** (same engine, more RAM): delays up to ~2 s, Freeze up to 2 s, pitch change to +/-2 octaves at 1-cent resolution, wider ranges throughout; all 30 preset names retained. Source: [SPX90II page](https://www.vintagedigital.com.au/yamaha-spx90ii-multi-effects-processor/). Confidence: **High**.

### 2.3 Yamaha reverb patents from the era

These describe the design school the SPX90 came from. None is a published listing of SPX90 microcode — they are structural evidence, not a spec.

| Patent | Title / assignee | Relevance | Source |
|---|---|---|---|
| **US 4570523** | Reverberation tone generating apparatus — Nippon Gakki Seizo K.K. | Combines an **irregular-delay/irregular-level** section (early reflections) with a **feedback-loop** section producing regular delay/level (the tail), explicitly to get natural reverb "with circuits of a small size". Describes a shared delay RAM with write-address generation and read-address generation offset by a delay-time parameter — precisely the YM3804 read-address model. | [FPO 4570523](https://www.freepatentsonline.com/4570523.html) |
| **US 4586417** | Electronic musical instruments provided with reverberation tone generating apparatus — Nippon Gakki, 1986, Kato et al. | Same family | [FPO 4586417](https://www.freepatentsonline.com/4586417.html) |
| **US 4706291** | Reverberation imparting device — Nippon Gakki, filed 1986-06-23 | **Fixed-type convolution** over a pre-memory using the *initial* reflected-sound parameters, plus **adaptive-type convolution** over the main data memory using the remaining reflection parameters, summed; plus a **time-varying frequency-characteristic control** on the reverb output. A direct description of "ER by explicit tap convolution, tail by a cheaper adaptive scheme, with damping that changes over the decay". | [FPO 4706291](https://www.freepatentsonline.com/4706291.html) |

Confidence: **High** that these are Yamaha/Nippon Gakki reverb patents of the right era; **Med** that they describe the SPX90's specific structure — assignee, dates and the shared-RAM read/write-address architecture all line up with the YM3804, but no patent names the SPX90.

### 2.4 Why it sounds metallic, ringy and grainy

Physically grounded reasoning from the confirmed hardware. Confidence **High** on the mechanisms, **Med** on their relative weighting.

1. **64 instructions per sample.** The whole reverb — every comb/allpass stage, all filtering, all tap accumulation — must fit in 64 operations. That forces very low echo density. Sparse modal spacing is *the* origin of the metallic ring. A modern reverb spending hundreds of ops per sample cannot sound like this even with an identical topology. This is the dominant factor and it is a *budget*, not a stylistic choice.
2. **31.25 kHz with a 12 kHz brickwall.** Everything above 12 kHz is gone, and the steep analogue filter contributes its own phase smear plus a bright resonant lift just below the corner.
3. **Linear 16-bit, no dither, near-certainly truncating fixed-point arithmetic in the feedback loops.** Long tails quantise into a granular, buzzy decay floor. The >75 dB reverb figure versus >81 dB for delay is direct published evidence that the recirculating reverb loop itself adds ~6 dB of extra noise — that delta is a measurable target for a model.
4. **Shared ~16 kWord delay RAM.** All taps come from one buffer, so tap times are quantised to integer samples at 32 us granularity.
5. **YM3807 LFO modulation of read addresses**, likely with little or no fractional interpolation — a further source of grit that a smooth interpolated-delay modern reverb will not reproduce.

### 3.2 Prior modelling work — the headline finding

**No plugin exists that claims to be an algorithmic or circuit-level model of the SPX90 reverb.** Nothing from Audiority, TAL, Eventide, UAD, Arturia, Softube, Baby Audio, Fuse Audio or GSi. The consistent community answer to "is there an SPX90 plugin" is "use IRs" ([KVR](https://www.kvraudio.com/forum/viewtopic.php?t=171215), [KVR](https://www.kvraudio.com/forum/viewtopic.php?t=551970), [Gearspace](https://gearspace.com/board/so-much-gear-so-little-time/390507-plugin-recreates-yamaha-spx90.html)). Confidence: **High**. This is the opportunity — the niche is genuinely unoccupied.

What does exist:

* **[Nomad Factory 80s Spaces](https://www.nomadfactory.com/products/p3054-80s-Spaces/)** — lists the SPX90 among 12 "reference reverb models" alongside 480L, EMT 250, RMX16. **Convolution**, 250 IRs, not an algorithmic model. Confidence: High.
* **[Witch Pig "SPX Nevermore"](https://www.witchpig.co.uk/plugins.html)** (free VST3, [KVR](https://www.kvraudio.com/product/spx-nevermore-by-witch-pig)) — models only the **Symphonic** preset, not reverb; inspired-by, with "Noisy" and "12 Bit" switches. Note its product page calls the SPX90 "a budget 12 bit digital FX unit" — **this is wrong**; Yamaha's own spec says linear 16 bit, and the parts list contains a 16-bit PCM54HP DAC. Confidence: High that the 12-bit claim is folklore.
* **[Valhalla VintageVerb](https://valhalladsp.com/shop/reverb/valhalla-vintage-verb/)** — 1970s/1980s/Now colour modes, and modes like Palace ("loosely inspired by a classic 1980s room simulator algorithm, but updated to allow higher echo density"), Chamber1979, Hall1984. Costello's acknowledged reference is the **Lexicon** lineage, not Yamaha, and he is explicit that these are inspired-by with improvements the hardware could not do. ([modes writeup](https://valhalladsp.com/2023/02/10/valhallavintageverb-the-modes/), [4.0.0](https://valhalladsp.com/2023/12/13/valhallavintageverb-4-0-0-new-reverb-modes-chamber1979-and-hall1984/)) Confidence: High.
* **ValhallaSpaceModulator** — reported secondhand as inspired by the SPX **Symphonic** patch. Confidence: Med.
* **[StompTones "Loveless"](https://stomptones.gumroad.com/l/Loveless)** — reverse reverb citing SPX90 reverse-reverb behaviour among influences. Confidence: Med.

### 3.3 Reverse engineering — a genuine void

**No ROM dump, no firmware disassembly, no published spectrogram or gate-level analysis of the SPX90 was found.** Searches surfaced only EPROM sales listings (e.g. a [v1.2 firmware EPROM on Reverb.com](https://reverb.com/item/78097977-yamaha-spx-90-version-1-2-firmware-os-update-eprom-spx90-rom-chip-efx)) — which proves the *host CPU* ROM circulates and is dumpable, though the DSP microcode lives inside the YM3804 mask. A useful methodological template for such a project is [JKN0/PSR70-reverse](https://github.com/JKN0/PSR70-reverse) (Yamaha PSR-70 / YM3806 / YM2154). Confidence: **High** in this negative.

Useful behavioural analyses that do exist:

* [Vintage Digital SPX90 review](https://www.vintagedigital.com.au/product-review/yamaha-spx90-review/) — describes the ER programs (Hall/Random/Plate/Reverse) as modelling only the **first reflection cluster with no tail**, with the initial Delay parameter offsetting onset by 50–100 ms. This independently corroborates the E/R 2 typing of GATE REVERB and REVERSE GATE. Confidence: Med, but consistent with the manual.
* [Fractal forum, recreating the ER-Reverse patch](https://forum.fractalaudio.com/threads/spx-90-early-reflections-reverse-shoegaze-classic-block.212534/) — a player's reconstruction claiming the sound is essentially **pre-delay plus about three taps, no long tail, no feedback**. Confidence: Med (not a measurement, but it matches the ER program description).
* [Sound On Sound, "Hands On: Yamaha SPX90" (Dec 1991)](https://www.muzines.co.uk/articles/hands-on-yamaha-spx90/7549) — contemporary review noting "a noticeable dulling of high frequencies" from the reduced sample rate, with otherwise good noise and distortion performance. Confidence: High.

### 3.5 Yamaha reverb lineage

Sources: [Vintage Digital REV series](https://www.vintagedigital.com.au/series/yamaha-rev/), [SPX2000 page](https://www.vintagedigital.com.au/yamaha-spx2000-multi-effect-processor/), [Yamaha SPX2000](https://europe.yamaha.com/en/business/audio/products/processors/spx2000/index.html), [SOS SPX2000 review](https://www.soundonsound.com/reviews/yamaha-spx2000). Confidence: **Med** (largely one enthusiast publisher).

REV1 (1984) is Yamaha's first digital reverberator; REV7, REV5, REV100 follow. **SPX90 (1985) is the cost-reduced descendant — a different, cheaper engine (31.25 kHz / 12 kHz bandwidth), not a REV7 in a small box** — though it shares the YM3804/YM3807 silicon, which is why they are sonic cousins. SPX900/SPX1000 (early 90s) raise the rate to full 20 kHz bandwidth. SPX2000 (2003) keeps the SPX interface and legacy programs but adds **new REV-X** algorithms at 24-bit/96 kHz, and **REV-X is explicitly presented as new, not as SPX90 heritage**. There is no documented algorithmic continuity from SPX90 into modern Yamaha/Steinberg REV-X to lean on. That is a real gap, not a search failure.

## 4. Use on 1980s thrash and metal records

**The premise did not survive the search, and this needs saying plainly.** Across Mix, Sound On Sound and Tape Op interviews with the four engineers most central to the scene — Flemming Rasmussen, Alex Perialas, Scott Burns, plus Andy Wallace — **the SPX90 is never mentioned once**.

### What named engineers actually say

* **Rasmussen on *Master of Puppets*** — his stated philosophy was anti-reverb: the band wanted an in-your-face sound and "'no reverb!' was the mantra," so "that meant instead that I recorded a hell of a lot of ambience tracks," using the cavernous rooms at Sweet Silence. Gear named: Trident A-Range, UREI 1176, LA-4A, Aphex EQ, UREI 530, Orban 622B, "AMS delays" and "Lexicon delays" — described as **delays, not reverbs**. [Mix, Classic Track](https://www.mixonline.com/recording/classic-track-master-of-puppets-metallica). Confidence: High.
* **Rasmussen on the Justice-era drums** — "what made the drums sound so grand on those albums were the room mics that we used in the studio in Copenhagen"; he believes the Justice mixers "just used the close mics". No effects units named at all. [SOS, Classic Tracks: "One"](https://www.soundonsound.com/techniques/classic-tracks-metallica-one). Confidence: High.
* **Rasmussen, Tape Op** — mic technique only (B&K 4006 omnis 10–15 ft out; AKG "The Tube" 45 deg off the cab corner, 3–6 ft). [Tape Op](https://tapeop.com/interviews/172/flemming-rasmussen-riding-the-sweet-silence). Confidence: High.
* **Alex Perialas, Pyramid Sound (Anthrax, Testament, Overkill)** — detailed on tracking, silent on outboard reverb. Guitars "mic'd with 57s and 421s. Simple close mic'ing, but 99% of getting those guitar tones was about pickups and pickup height." Four guitar performances panned as tracked. [Tape Op](https://tapeop.com/interviews/128/caught-mosh-alex-perialas). Confidence: High.
* **Scott Burns, Morrisound** — the only processor he names is the **TC 2290**: "one of the first to get a TC Electronic 2290 delay sampler, which enabled them to get that big drum sound", and "I took the TC 2290 from the A Room and the one from the B Room, sampled his real kick sound, triggered them live through a noise gate." [Tape Op](https://tapeop.com/interviews/173/scott-burns). Confidence: High.
* **Andy Wallace on *Reign in Blood*** — reverb used sparingly; the intent was that the listener "feel like you were in a boxing match and just kept getting punched in the face." [Louder](https://www.loudersound.com/bands-artists/andy-wallace-on-working-with-nirvana-rage-against-the-machine-slayer-jeff-buckley). Confidence: Med (read via search summary).
* **Testament, *The New Order*** — "Effects were kept minimal — reverb and slight delay for leads, and an overdrive pedal to tighten the rhythm sound." No unit named. [riffology.co](https://riffology.co/posts/testament-the-new-order/). Confidence: Low (unsourced blog).

### Claims explicitly NOT verified

None of the following could be supported at any confidence level, and no quote or URL was invented to fill them:

## 5. Where "exact 1:1" breaks

### What can be matched to a null

* **All finite-impulse-response programs** — EARLY REF. 1/2, GATE REVERB, REVERSE GATE, DELAY, ECHO (feedback at 0), and the PARAMETRIC EQ. These are linear and time-invariant at fixed parameters. Capture the impulse response at 31.25 kHz (or oversampled and decimated) and you have the algorithm exactly, tap for tap. For the ER programs you can go further: deconvolve to recover the literal tap positions and gains, then rebuild them as an exact sparse FIR, which also lets you interpolate correctly between ROOM SIZE / LIVENESS settings instead of storing hundreds of IRs.
* **The recirculating REV 1–4 programs at fixed parameters, to within the nonlinearity of quantisation.** They are *nominally* LTI, so an IR capture nulls well at moderate levels. Where it degrades is in the deep tail, where truncation quantisation is signal-dependent and an IR convolution reproduces the average behaviour but not the granular texture.
* **The analogue I/O colouration**: input stage, 12 kHz anti-alias and reconstruction filters, output stage. Measurable directly by sweeping in bypass and in effect mode and taking the difference.
* **All parameter ranges and the parameter-to-coefficient mapping**, by sweeping a parameter and measuring decay time / tap positions / cutoff at each step. This is tedious but fully determinate.

### What cannot be matched exactly

* **The YM3804 microcode.** It is mask ROM inside a custom LSI. No dump, disassembly or published instruction set was found. The exact ordering of comb/allpass stages, their delay lengths, and the coefficient set are unknown and can only be inferred from measurement.
* **The internal arithmetic.** Word width of the accumulator, rounding vs truncation, saturation vs wrap on overflow, and where headroom is scaled are all undocumented. These determine the *character* of the grain and the behaviour when the reverb is driven hard — exactly the regime a metal snare lives in. This must be approximated by hypothesis-and-test: implement a candidate fixed-point scheme, feed a hot signal, and compare the noise-floor spectrum and the intermodulation products with the hardware.
* **Any time-varying or nonlinear behaviour**: the YM3807's LFO modulation of tail read addresses, the modulation programs, PITCH CHANGE (inherently time-varying), the GATE/COMPRESSOR dynamics, FREEZE. IR capture is inapplicable; these need parametric modelling validated by A/B measurement of specific test signals.
* **Unit-to-unit variance.** Analogue stages drift and components age. Two SPX90s will not null against each other. Pick one reference unit, characterise it, and state that the model targets that unit.

### Recommended validation protocol

1. Reference unit: SPX90 (and an SPX90II if the extended ranges matter). Set +4 dBm in/out, effect balance 100 % wet, bypass off.
2. Capture per preset at factory-default parameters, then on a parameter grid: log sweep and MLS, plus a dry-null pass, at 96 kHz on the analogue outputs.
3. Per preset, report null depth against the model in three bands (below 1 kHz, 1–8 kHz, 8–12 kHz) and separately report tail noise-floor spectrum, which is where a naive model will fail.
4. Accept criteria: FIR-class programs should null to better than -60 dB. Recirculating reverbs will not; target matching RT60 per octave to within 5 %, matching the modal density, and matching the tail noise-floor spectrum shape, then judge by ear on a snare and a rhythm-guitar track.

## 6. Recommended modelling strategy

A hybrid, in this order:

1. **Structural model, not convolution.** Build a sparse multitap early-reflection generator plus a small comb/allpass tail, deliberately constrained to a ~64-operation-per-sample budget. The budget is not a curiosity, it is the sound.
2. **Run the core at 31.25 kHz** inside the plugin, with proper resampling either side and a modelled ~12 kHz brickwall. Do not run the algorithm at host rate and lowpass afterwards; the modal spacing and the integer-sample tap quantisation are rate-dependent.
3. **Fixed-point arithmetic with truncation** in the feedback loops, 16-bit converters, no dither. Tune the word width and rounding until the measured tail noise floor matches the hardware and the reverb-vs-delay dynamic range delta lands near the published 6 dB.
4. **Integer-sample (non-interpolated) tap reads**, with LFO modulation applied to read addresses in the YM3807 manner.
5. **Calibrate against the Surefyre SPX90II IR grid** rather than a single capture. It already covers the parameter space (damping x 27 reverb lengths; liveness x 20 room sizes), which turns coefficient fitting into a solvable optimisation instead of guesswork.
6. **Deconvolve the ER programs to recover literal tap positions and gains.** Those four programs are finite and LTI, so they can be reproduced exactly, and recovering the taps lets the model interpolate correctly between ROOM SIZE and LIVENESS settings.
7. **Acquire a real unit for validation** (or an FX900/R100 as a cheaper YM3413-based cousin). Everything above is a hypothesis until it is measured.

State in the product copy what is matched by measurement and what is approximated. The microcode is closed; honesty about that is cheap and the alternative ages badly.
