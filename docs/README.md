# SushiDSP documentation

The manual's index. Start at the root [`README.md`](../README.md) if you haven't; this is for
once you're in the tree and need a specific document.

## Where to go

- **[Design](design/sushidsp.md)** — the architecture, the math, the SOLID rationale, and the
  product roadmap (D0–D7). This is the authoritative spec an implementer builds from; it
  describes intent and may describe work that does not exist in the tree yet.
- **[Contributing](CONTRIBUTING.md)** — the conventions every change is held to: C++17, Allman
  braces, the license header format, the test/CTest-label layout, and how to build (`sd`, never
  `cmake` directly).
- **[Changelog](reference/CHANGELOG.md)** — what changed and when, by roadmap phase.
- **[Code of Conduct](CODE_OF_CONDUCT.md)** and **[Security Policy](SECURITY.md)**.
- **[`docs/reference/spice/`](reference/spice/)** — the SPICE reference corpus: netlist-directive
  `.asc` files and Koren/Norman `.sub` models for each circuit block, exported to CSV by
  `tools/spice/export.py` and read back by `tests/measure/SpiceCsv.hpp`. Populating it needs
  LTspice, which is a user-side step — see the changelog's D6a entry.
- **[`include/SushiDSP/math/dk/`](../include/SushiDSP/math/dk/)** — the DK-method circuit core:
  `DenseLu` (fixed-size LU), `DampedNewtonSolver`, `DkNetlist` (the control-thread netlist
  builder) and `DkCircuit<S, N, I, O>` (trapezoidal discretisation and the per-sample solve).
  Header-only, standard library only, and it never names a circuit model — the models arrive as a
  template parameter. Design spec §4.5, "As built in D6b".
- **[`include/SushiDSP/math/Resampler.hpp`](../include/SushiDSP/math/Resampler.hpp)** — the
  arbitrary-ratio polyphase resampler, for a conversion ratio that moves while audio runs (the
  DD-3's clock is the first consumer). One fractional phase accumulator walks the prototype in
  `ResamplerCoefficients.hpp`, generated by `tools/dsp/design_resampler.py`; a rate change moves
  the accumulator's step and never rebuilds a bank. `latency_seconds()` reports availability
  look-ahead, `34 / min(source, target)`; the converter is zero phase, so output time *t* carries
  input time *t* and subtracting the number as an alignment offset is wrong. Design spec §4.4.
- **[`include/SushiDSP/circuits/models/`](../include/SushiDSP/circuits/models/)** — the device
  laws the solver calls back into: `SiliconDiode`, `Triode12AX7`, `PentodeEL34`, and the shared
  `SoftTransition` softplus/logistic helpers. Each exposes `current` and `jacobian` in `double`
  against its `.sub` file's exact constants, and is C¹ everywhere.
- **[`modules/dd3/`](../modules/dd3/)** — the Boss DD-3 delay, `sushidsp.dd3`. Its
  [`README.md`](../modules/dd3/README.md) says which revision is modelled, which class owns which
  block, the three constants that are calibrations rather than component values, and what is left
  out; the spec is
  [`docs/superpowers/specs/2026-09-05-dd3-spx90-design.md`](superpowers/specs/2026-09-05-dd3-spx90-design.md).
- **[`tools/`](../tools/)** — developer-side scripts that are not part of the shipped library:
  `tools/dsp/design_halfband.py` (regenerates `include/SushiDSP/math/HalfbandCoefficients.hpp`
  from a scipy `remez` design), `tools/dsp/design_resampler.py` (regenerates
  `include/SushiDSP/math/ResamplerCoefficients.hpp` from a Kaiser-windowed sinc, and fails if the
  design stops clearing −100 dB) and `tools/spice/export.py` (runs the SPICE corpus above through
  LTspice and exports its output to CSV).
- **[`tests/measure/`](../tests/measure/)** — the test-side measurement library (`render`,
  `thd`, `alias_floor`, `frequency_response`, `null_test`) every product's plausibility and
  alias-floor test is built on.
- **[`tests/circuits/`](../tests/circuits/)** — test-side circuit descriptions shared across the
  unit tests and the benchmark, so the same block is not transcribed twice. Currently
  `JcmV1aNetlist.hpp`, the JCM800 V1a stage as a `DkNetlist`.

## Generated API reference

`sd doxygen` builds `docs/api-site/html/` from the headers under `include/SushiDSP/`, starting
from [`docs/api/mainpage.md`](api/mainpage.md). It documents what the headers say; it is not a
substitute for the design spec's reasoning.

## Implementation record

`docs/superpowers/plans/` holds the implementation plan for each roadmap phase (D0, D1, D2, …),
each with a `- [ ]` checklist of TDD steps. They are historical execution records once a phase
merges — later phases may use different tooling or conventions, and an old plan is not updated
to match; read the design spec for the current state, not an old plan.
