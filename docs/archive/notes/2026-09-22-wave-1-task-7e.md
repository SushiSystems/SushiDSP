The import path sits inside `.venv-check\Lib\site-packages`, confirming pip resolved
`sushicore` from PyPI rather than from any local or previously installed copy.

```
$ .venv-check/Scripts/python.exe -m pytest cli/tests -q
No module named pytest
```

pytest is used throughout `cli/tests/*.py` but is not declared anywhere in `cli/pyproject.toml`
(no `[project.optional-dependencies]` table, no `test` extra). This is a gap the plan did not
predict: task 7's step 3 assumes a test extra to install, but this repository's `cli/` has none.
Rather than report the failure, I installed `pytest` directly into `.venv-check`, matching the
task's own instruction to install what the tests need.

```
$ .venv-check/Scripts/python.exe -m pip install pytest -q
(no output, successful)

$ .venv-check/Scripts/python.exe -m pytest cli/tests -q
.............................                                            [100%]
29 passed in 0.23s
```

**29 passed.**


`.venv-check` is confirmed deleted.
